## Findings driving this revision

One unchanged, uninterrupted full dev.4 invocation completed all 142 packages in
2,774.137 seconds: 138 passed, three failed, one had no tests; 16,335 test events
passed, four failed, and 55 allowed skips passed the skip budget. All source hashes
were unchanged and all package terminals were present exactly once. Its failures
are preserved, not replaced by selected passing retries.

- Two YAML-only configuration tests inherited the integration fixture's runtime
  DSN. The helper now clears that variable for each YAML test while preserving
  all assertions and separate environment-precedence tests. Independent review
  accepted the correction. Whole config/schema/testdb packages pass race/coverage
  with both integration/e2e tags after the fixture corrections.
- The migration fixture omitted the new maintenance child table from its explicit
  teardown inventory. It now drops that child before the parent, preserving the
  foreign key and checking recreation/idempotence. No CASCADE bypass was added.
- The maintenance ledger lacked a declared retention owner. Deeper review found
  that old concluded cases could cascade active maintenance and ordinary retention
  could remove its rollback/audit records. A declaration alone is insufficient.
- A complete native dev.5 candidate run exposed a real upgrade defect: an older
  nine-state maintenance check remained unchanged by `CREATE TABLE IF NOT EXISTS`
  and rejected the supported `uncertain` state. The candidate run stays **red**
  (78 passing, one failing, two explicit skips); its attempted action does not
  count as rollback acceptance. Bootstrap now atomically upgrades and validates
  the owned check. Tests cover old rows, all ten supported states, unknown-state
  refusal, misleading same-literal expressions, unvalidated checks, failed
  validation rollback, and the current-schema fast path preserving its OID.
- The focused upgrade run also exposed backward database wall-clock movement:
  a conclusion preceded its lease start by more than 72 ms, producing negative
  active time. Deterministic regressions reproduce both the check violation and
  silent refund of previously charged time. Elapsed lease and orphan charges now
  clamp the increment at zero before adding it; existing caps and fencing remain.
  The observed clock movement belongs to the local PostgreSQL test environment;
  this is not evidence of a Lakebase clock fault.

## Maintenance retention contract

The correction is implemented and independently approved after 56 focused
race-enabled test/subtest events passed with zero failures. SRE timeline
retention owns the proposal via its existing cascade. Both evidence and timeline
must retain active/unresolved maintenance and age finalized work from its latest
maintenance change. Queue, action, finding, verification and decision dependencies
must survive while the maintenance ledger needs them, including an execution-log
commit followed by failure to save its returned action ID. Finalized expired work
must eventually release these holds.

Typed maintenance requires colocated control and monitored database bindings.
The constructor refuses a split topology, and runtime wiring withholds only this
bridge while preserving ordinary SRE observations and existing actions. No
cross-database retention hold system is claimed. Separate pools for the same
verified endpoint/database remain supported. The six-case runtime construction
regression tests this without opening connections to its closed loopback targets.
App workload-table execution remains unproven; observation trust stays active.
