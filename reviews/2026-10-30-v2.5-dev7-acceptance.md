## Final-review defect

The loaded dev.6 Cases review exposed precision loss in query identities: a signed
64-bit PostgreSQL query ID decoded through a floating-point JSON value was
rounded in evidence chips and generated investigation artifact names. Exact
`object_identifier`/case identities remained intact. The fix preserves query IDs
as decimal strings, repairs historical compatible values at the response boundary,
and withholds artifacts when an exact ID is unavailable or conflicts. Ordinary
metric decoding and Ask grounding checks stay intact. Independent review and
focused integration tests passed.

The full affected API/Cases race run passed 1,421 tests/subtests, with zero
failures and one explicit live opt-in skip. Real App checks verified exact
positive/negative signed64 IDs in Findings GET, Cases evidence and generated
filenames. Fleet shows the connected database; a fresh Ask request returns four
statements and one citation, including exactly 2834 blocks written and 2794 read,
with no dropped claims or created actions. Desktop/mobile checks have no console,
page or unexpected HTTP errors. Databricks auth, App-SP OAuth M2M Gateway,
readiness and all seven immutable runtime file hashes passed. Frontend assets
are byte-identical to the dev.6 build, whose 676 unit tests/45 browser tests and
22-route responsive checks remain separately recorded.

## Demonstration state and platform boundaries

Nine new fixture families were detected and projected into Cases:
duplicate indexes, missing FK indexes, stale statistics, dead-tuple bloat, heavy
sequential scans, invalid indexes, near-limit sequences, a default-threshold slow
query, and the new hint-free temporary-spill/work_mem finding. Existing work
items were not manually changed or deleted. No findings were manually inserted. Cases projection
does not mean each finding automatically opened a durable SRE investigation.

All workload generators have stopped. The inert App demo schema occupies about
13.15 MiB; the explicit guarded cleanup is:

```sh
python3 scripts/lakebase-nerdlab.py cleanup
```

That command removes only the manifest-owned fixture objects after exact
identity/owner checks. It does not reset query counters or delete retained
findings/cases. Native test fixtures and own temporary metadata were cleaned.
The App stays in observation mode, using Databricks-only sign-in and OAuth M2M
for Unity Gateway; no Gateway API key is configured.

This is not full PostgreSQL parity. Active hints/work_mem promotion and HypoPG
retain provider restrictions. Advanced telemetry is a working asynchronous
history path, separate from the unavailable standard session auto_explain hook;
the App's consent remains metadata-only. Unobserved selective counter reset or
eviction/regrowth can defeat per-query interval lineage. Default multi-day
windows, deliberate failure/pressure incidents, some plan-dependent optimizers,
custom descending sequence ranges and unconfigured external SRE sources remain
unproven, as individually listed in the matrix.

Earlier complete repository coverage belongs to dev.5 (142 packages). The
dev.6 frontend/browser/analyzer proofs and dev.7 affected-package checks must
be assessed at their recorded revisions; no whole-repository dev.7 rerun is
implied. Individually identified private evidence stays under
`.local-test-results/`; it is not a distributable attachment.
