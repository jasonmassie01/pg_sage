## Current validation and compatibility limits

The final full changed-package checks pass: auth 270 events, API 1,318 events
with one opt-in native-only skip, command 586 events, and frontend 646 tests.
These run locally against the isolated PG17 fixture, with backend race checks
and union integration/e2e tags. The small host-normalization fix then passes
focused auth/API/command startup race regressions and pinned lint. The prior
full Go composite is historical and is not presented as a fresh dev.2 run.

Ubuntu 22.04 and libpg_query checks pass. Live App acceptance is in the

**This is qualified development compatibility, not full Lakebase/SRE parity.**
The native evidence below establishes core collection, advisors, selected
operator actions and Gateway/App behavior. It does not establish a completed
native SRE investigator, SLO or runbook loop. The 1,154 local SRE pass events
include scripted/fake-model fixtures and are not native incident acceptance.
Programmatic MCP/specialist/signed-ingest protocols retain their scoped inner
credentials; this work does not certify those clients as platform-token-only.

Lakebase provides Beta `system.lakebase` plans, logs, ASH/DDL and compute
telemetry, but pg_sage has no reader. Standard auto_explain logging is disabled
on the tested endpoint while separate provider capture flags are already on.
Fresh account-wide telemetry exists; selected `<test-project>`/pg_sage resource rows
were not found, so coverage/routing remains unresolved. Hints cannot be
activated in the tested native configuration; HypoPG is absent. Enabling
telemetry alone does not fix these integration, privilege or testing gaps.

### Supported boundary

Eight Lakebase action contracts are explicitly enabled:
`analyze_table`, `vacuum_table`, `create_index_concurrently`,
`revert_created_index`, `reindex_concurrently`, `create_statistics`,
`revert_created_statistics`, and `alter_database_guc`. Ownership, policy,
maintenance, trust and replica checks still apply. Database-setting actions are
restricted to the connected database and supported user-context settings.
Statistics actions reject IF NOT EXISTS so rollback cannot drop an existing
object. Catalog success alone does not establish a performance gain.

HypoPG, direct server log-file/OS access and ALTER SYSTEM are unavailable.
Lakebase offers Beta execution-plan, log and compute telemetry in `system.lakebase`,
but pg_sage has no connector for it yet; enabling the preview alone does not
complete SRE observability. See the [Advanced Telemetry gap assessment](2026-10-29-lakebase-advanced-telemetry.md).
On the tested PG18
endpoint, pg_hint_plan installs but its hook cannot be enabled, and pgAudit
installation is refused. The App principal lacks CREATEROLE, so governance is
posture-only. Brokered SCRAM roles cannot be replaced with workspace OAuth;
project-wide native-password settings were not changed. Built-in transaction
pooling is outside native OAuth support. HA/failover, UC-only expired-claim
authorization, multi-day reliability and full self-managed PostgreSQL parity
remain unverified. This is a development release with a tested managed-service
boundary.
