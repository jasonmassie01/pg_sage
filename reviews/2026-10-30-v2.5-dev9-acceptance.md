# pg_sage 2.5.0-dev.9: Cases and Actions UX

Date: 2026-10-30. Development branch: `lakebase-databricks-app`.
Implements the approved [first-time-user review](2026-10-30-first-time-user-ux-review.md).
This is a product/workflow improvement and correctness release, not a new claim
of full Lakebase feature compatibility or a usability study with novice users.

## Delivered behavior

| Area | Result |
| --- | --- |
| Cases | Plain-language conditions, observed measurements, qualified consequences, explicit unknown urgency/impact and a next step. Sequence, spill, duplicate/unused/missing indexes, stale statistics, slow queries, bloat, sequential scans and invalid indexes have contextual summaries. |
| Expert evidence | Exact identifiers, source text, counters, SQL, guardrails, recovery artifacts and action timelines remain available under expandable details. Missing data is not replaced with reassuring defaults. |
| Focused review | Review case opens one case. Database and case identity survive links to Actions and Ask Sage; changing database clears the old case context. |
| Ask Sage | Explain this prepares an explanation-only question with exact source identity. It does not send automatically. Missing, unavailable and mismatched case context are distinguished. Long technical identities cannot truncate the explanation-only instructions. |
| Suppression | Secondary control explains that hiding a finding does not repair the condition. |
| Actions | Opens Proposed changes; separate Needs your review, In progress and History views. Counts describe loaded scope and pagination; time-range applicability is explicit. |
| Change decisions | Real risk is separate from execution mode. Inline restrictions, recovery limits and verification unknowns remain visible. Approval acceptance is distinguished from confirmed SQL execution and verified improvement. SQL controls say Approve and run; external commitments remain distinct. |
| Index baseline | Safety panel is expandable and explains that collecting a baseline does not enable execution in Observation mode. |
| Global context | Selected database, reported mode, connection and collection timestamp appear before page content. Mixed fleets and unknown policy are qualified. Failed status refreshes do not imply health. |
| Nerdy theme | Original page-specific DBA/Postgres memes remain on every page as a compact footer. |
| Unnamed index recovery | No guessed `ON` index name, fabricated inverse or invalid regclass verification. Recovery is unknown until the actual created object is established. |
| Other recovery claims | Dropped indexes need a matching captured recreation definition. Comment-only/manual plans are not complete rollback procedures. A fabricated role work_mem RESET is not presented as restoration of an uncaptured prior setting. |
| Preflight | Unreported activity, lock, lag, size and rewrite evidence stays unknown. Explicit measured zero is distinguishable from missing data. Estimated DDL lock behavior is not a live lock measurement. |
| Managed settings | Lakebase-inapplicable ALTER SYSTEM procedures are withheld from proposed runnable artifacts and replaced with applicability context; source evidence remains available. |

## Boundaries and remaining work

- The deployed App remains in Observation mode. This review does not approve
  execution, automatic SRE investigations, notifications, broad grants or extra
  fixture workload scans. Existing fixtures remain for inspection.
- Case explanations describe database evidence. They do not establish application
  ownership, customer impact, a deadline, or measured performance improvement.
- Actual first-time-user usability testing is still needed. Component tests,
  independent heuristic review and a browser walkthrough do not substitute for it.
- Explicit fixture classification is not yet part of Cases evidence. We do not
  label arbitrary schemas as synthetic based on their names. The retained
  `nerdlab_20261030` objects are controlled test fixtures, documented in the
  [scenario report](2026-10-30-nerdlab-findings.md); the database also has earlier findings.
- Provider restrictions and unproven long-running/pressure scenarios remain in
  the [compatibility findings](2026-10-30-provider-compatibility-gaps.md).
  This UX update does not make hints, HypoPG or session auto_explain available.
- Source tree contains the cumulative task-owned changes from prior development
  revisions. Binary source fingerprints, rather than the unchanged base commit
  alone, identify the built code.
