## Final behavior

- Cases lead with plain-language observations, possible consequences, known
  restrictions and a next step. Unknown urgency, missing measurements and
  unproven application impact remain explicit.
- Exact SQL, original evidence, plans, recovery, checks and timelines remain
  available through progressive disclosure. Suppression is secondary and
  explicitly does not fix the condition.
- Review case, Actions and Explain this preserve database and case identity.
  Ask Sage prepares an explanation-only draft and waits for the user to send.
- Actions defaults to Proposed changes, with Needs your review, In progress and
  History. Accepted approval, SQL execution and measured improvement are distinct.
- Mode/scope/collection context appears before page content. DBA memes remain
  on every page in a compact footer. Observation mode remains active.
- Unnamed indexes do not receive guessed inverse SQL or invalid catalog checks.
  Missing recovery is unknown; unmeasured preflight checks are not passes.
- Provider-inapplicable system-setting procedures are withheld, including older
  saved SQL when current applicability guidance rejects it.
- Equivalent action aliases for the same exact database and source are one
  review item. The saved proposal and current case guidance retain separate
  risk/recovery claims; a source match does not validate old SQL.
- Stored inverse SQL is shown as a matching recovery procedure only when its
  forward and inverse text match the current reversible procedure. Otherwise
  it is withheld with the reason. The stored record is not rewritten.

## Remaining boundaries

Actual first-time-user usability testing remains outstanding. This work uses
independent heuristic reviews, component tests, source inspection and a real
browser walkthrough; it does not establish novice comprehension empirically.

Explicit fixture labels are not yet part of Cases evidence. The retained
`nerdlab_20261030` objects are controlled development fixtures documented in the
[scenario report](2026-10-30-nerdlab-findings.md), alongside earlier findings.
The UI does not infer that arbitrary schemas are synthetic from their names.

This release does not establish full Lakebase compatibility. Hints/HypoPG,
session auto_explain and other provider restrictions, along with unproven
multi-day/pressure scenarios, remain documented in the
[compatibility findings](2026-10-30-provider-compatibility-gaps.md).
Databricks-only sign-in and App OAuth M2M for Unity Gateway are retained; no
Gateway API key is introduced.
