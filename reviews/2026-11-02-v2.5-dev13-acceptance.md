# dev.13: 50 shuffled memes and standalone Settings

This UI follow-up builds on [dev.11–12](2026-11-02-v2.5-dev12-acceptance.md).
It does not replace the [Lakebase compatibility matrix](../docs/lakebase.md)
or claim a new whole-repository test run.

## Delivered behavior

The DBA breakroom now appears above page content, following monitoring context.
It contains 50 distinct original caption combinations using the six established,
locally bundled meme image templates. The image stays recognizable at small
sizes; adjacent text keeps captions readable on mobile. Images load eagerly
because the component is now near the top of the page. Existing
[image provenance and rights notes](../sidecar/web/public/memes/CREDITS.md) apply.
There are 50 captioned memes, not 50 different underlying template photographs.

A randomly shuffled deck survives navigation within the loaded App. Every meme
appears once per 50-card cycle, with no immediate repeat at the cycle boundary.
Navigating to a different page draws another card; query-string changes and
ordinary React renders do not. Reloading starts a fresh deck. A 60-second timer
also rotates cards, while Another meme and pause/resume controls support manual
browsing. Hidden tabs and focused controls do not consume cards. Reduced-motion
users start paused. The deck lives in memory: it stores no user, database or
URL information and makes no API/model/database request to choose a meme.
Changing image templates can fetch their same-origin JPEGs.

Settings incorrectly treated a connected standalone database as unavailable
because runtime inventory supplied managed registration ID zero. The corrected
page reads global configuration for an absent/zero ID, accepts that fallback
only when the server confirms standalone mode, and explicitly labels settings
as instance-wide. Managed registrations keep database-specific configuration;
missing fleet registrations still fail. Read-only policy and generation
protection remain active. No live settings were changed to verify this fix.

## Local validation

- All 777 frontend tests pass in 103 files, with no skips or failures.
- All 49 browser tests pass, with no skips, retries, unexpected failures or
  flaky results. They include all 50 memes at desktop and mobile sizes,
  same-origin image decoding, top-of-page visibility without scrolling,
  all 22 signed-in routes at both sizes, and standalone Settings loading.
- Deck tests cover unique captions/IDs, image signatures/dimensions, multiple
  complete cycles and cycle-boundary repetition. Component tests cover
  navigation, StrictMode, query privacy, timer reset/cleanup, pause/resume,
  visibility and keyboard focus.
- Settings tests cover standalone absent/zero IDs, save generation protection,
  existing reset feedback, managed database scope, missing fleet IDs, read-only
  responses, and loading/error states. No live save/reset was performed.
- ESLint, frontend production build and all 25 Python packaging tests pass.
- Twelve local screenshots cover the six templates at desktop/mobile widths;
  visual inspection confirmed the top placement and readable adjacent captions.
  Narrow compact sign-in cards can vary in height with long captions; the
  signed-in mobile card was stable across the 50-card check.

The first browser invocation did not run assertions because the downloaded
Playwright executable was absent. The accepted rerun explicitly used installed
Google Chrome. An earlier component run still had stale route-specific/lazy
image expectations; those tests were updated for the requested shuffle/eager
behavior. A subsequent focus-pause test exposed unreliable ancestor
`:focus-within` matching in the DOM fixture; explicit containment of the active
element now implements and verifies the intended focus behavior. These initial
failures are retained in private evidence, not counted as passing runs.

Node 26's experimental web-storage implementation conflicted with the existing
test environment. Tests use `NODE_OPTIONS=--no-experimental-webstorage`; this
changes the test runner, not production browser storage or App authentication.
