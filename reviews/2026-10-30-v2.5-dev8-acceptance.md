## Lakebase scenario results

Nine controlled families produced real findings natively and in the App:
duplicate indexes, missing FK indexes, stale statistics, dead-tuple bloat,
heavy sequential scans, invalid indexes, near-limit sequences, slow queries and
temporary spills. Native corrections resolved all nine at production thresholds.
The separate slow-query proof measured about 1202 ms against the unmodified
1000 ms threshold and demonstrated normal recovery without a statistics reset.

analysis proceeds; a projected finding is distinct from an automatic durable SRE
investigation. Historical total counts are timestamped evidence, not a promised
fixed inventory.

## Policy, retained fixtures and remaining limits

The App remains in observation mode. Databricks platform sign-in is the only App
login; Unity Gateway uses the App's OAuth M2M service principal, with no API key.
Lakebase connections use refreshed OAuth and verified TLS. Automatic SRE starts,
execution and external notifications remain disabled. Resource/config bindings
are preserved; no global Cleaner or SRE Runtime.Poll was run.

The inert owned demo fixtures remain for the selected operator’s UI review, about 13.15 MiB.
There is no active workload generator. Only disposable fixture objects received
test-local changes; no customer objects/provider settings/broad grants changed.
The guarded manifest/identity/owner-checked cleanup is:

```sh
python3 scripts/lakebase-nerdlab.py cleanup
```

Cleanup drops only those exact owned objects with RESTRICT. It does not reset
query counters or delete retained findings/cases/history. Native fixture objects
and own temporary metadata were cleaned. Evidence is individually identified
under private `.local-test-results/nerdlab-dev8-*`; credentials stayed in memory
and only the seven reviewed runtime files were uploaded.
The two task Docker containers and otherwise idle Colima VM were stopped after
validation; their volumes/caches were retained. Final integrity readback confirms
the active snapshot, all four full resource binding definitions unchanged and
all 2,033 source fingerprints unchanged.

Full PostgreSQL parity remains unproven. Active hints/work_mem promotion and
HypoPG retain provider restrictions. Advanced telemetry is a working asynchronous
history path, separate from standard session auto_explain; App consent remains
metadata-only. Counter comparisons cannot prove per-entry lineage through an
unseen selective reset or eviction/regrowth. Default multi-day windows,
deliberate pressure/failure incidents, some plan-dependent optimizer paths,
custom descending sequences, App-principal workload maintenance and unconfigured
external SRE feeds retain the specific limits in the matrix.
