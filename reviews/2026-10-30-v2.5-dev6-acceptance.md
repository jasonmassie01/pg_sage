## User-visible fixes

- Ask Sage's default/stored “All databases” scope and hidden singleton picker
  created a dead end. A single valid database now selects automatically, and
  the header picker remains available. Multiple databases offer a direct inline
  choice. Loading, empty, malformed and failed inventory states are distinct;
  a stale stored name cannot open a database before inventory validation.
- Fleet displayed a connected config-file database alongside “No databases
  configured yet.” Runtime/configured databases now have proper inventory rows,
  counts, connection health, platform/version, trust, open findings and an
  Inspect database link. Runtime inventory survives registration/configuration
  read failures with a truthful read-only/retry state.
- The shared shell now uses a graphite/navy Postgres control-room theme, mint
  accents, SQL grid, monospace labels, responsive navigation and original
  elephant-DBA illustrations with page-specific jokes. Every signed-in route,
  including empty/error/unsupported/not-found pages, has a meme. Standalone
  sign-in, SSO linking and the platform sign-in error screen have compact memes.
- New hint-free `temp_spill` findings report actual interval query-statistics
  evidence and controlled work_mem advice. No executable setting/value is
  guessed. Missing/truncated/idle/reset samples do not clear the category by
  absence; normal recovery requires a new observed non-spilling execution.
  Unknown epochs are rejected. Rules-source filtering and attribution include
  the new category.

## Real Lakebase findings and Cases

All nine controlled conditions produced real durable findings natively and in
this deployed App: duplicate indexes, missing FK indexes, stale statistics,
dead-tuple bloat, heavy sequential scans, invalid indexes, near-limit sequences
and temporary-file spills, plus a default-threshold slow query. Native corrections
resolved all nine at production
rule thresholds. The App's collector/analyzer detected the fixtures themselves;
no findings were manually inserted and no SRE cases were fabricated.

The final loaded Cases browser check showed 13 work items: nine new fixture
families and four existing items, including the older slow-query finding id 4.
The new slow-query finding is id 14. Direct scoped readback confirms that the
similar native slow-query timing did not leak into the App's database scope.

The UI's Cases surface projects findings into work items. That projection is
separate from a durable SRE investigation. The complete per-feature matrix,
scenario controls, limits and remaining uninduced conditions are in the
[Lakebase findings report](2026-10-30-nerdlab-findings.md). This is not universal
PostgreSQL/Lakebase compatibility certification.

## Remaining boundaries

Hints/active work_mem promotion and HypoPG retain provider restrictions. Standard
session auto_explain is separate from working advanced telemetry history; the
latter does not create synchronous hook parity or complete every plan-dependent
optimizer path. Counter deltas cannot prove per-entry continuity after an
unobserved selective reset/eviction and regrowth. Queryid findings do not
universally inherit fixture-schema filtering. Dangerous pressure/failure modes,
default multi-day windows, custom descending sequences and unconfigured external
SRE sources remain explicitly unproven in the linked matrix.
